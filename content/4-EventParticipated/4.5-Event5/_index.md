### 2. Layered Network Security on AWS

The technical topic that interested me most was **layered network security on AWS**.

Previously, when learning about VPCs, subnets, and Security Groups, I usually studied each service separately. This session helped me better understand how different components can work together to create a more secure system.

One important lesson was that security should not depend on a single control. Instead, it should be considered at multiple levels.

#### Protecting the Network Edge

This is where a system receives traffic from the Internet. Controlling incoming requests helps reduce the risk of unwanted traffic affecting an application.

#### Network Segmentation and Access Control

Different system components can be placed in separate network areas depending on their responsibilities.

For example, an application may need to receive requests from Internet users, but its database does not necessarily need to be directly accessible from the Internet.

Network configurations and Security Groups help define which connections are allowed between components.

#### Identity and Permission Management

Besides network protection, identity and access management are also important.

I learned that users and services should only receive the permissions necessary to complete their tasks.

#### Testing and Monitoring

Another point I remembered was the importance of verifying security configurations after implementing them.

For example, developers can test one connection that should be allowed and another that should be blocked to confirm that the security rules work as intended.

This helped me understand that **security is not only about configuring AWS services but also about continuously checking and maintaining those configurations**.

### 6. Connection to My LoveSpot Project

At that time, I was working on **LoveSpot**, an application designed to recommend dining locations and create itineraries in Ho Chi Minh City.

The project includes components such as the frontend, backend, AI service, and database. Therefore, the network security presentation encouraged me to think more carefully about how these components should communicate with one another.

While exploring the AWS architecture for LoveSpot, I identified several important considerations:

- **Access Control:** Allow communication between components only when necessary.
- **Database Protection:** Restrict direct Internet access and manage database connection permissions appropriately.
- **Network Testing:** Verify that required connections work while unnecessary connections are blocked.
- **Architecture Documentation:** Clearly explain the purpose of each service, the reasons for technical decisions, and testing results.

The presentation about student projects also reminded me that Workshop documentation should not simply list deployment steps. Explaining architectural decisions and recording testing results are equally important.

I would like to apply these lessons while improving LoveSpot and preparing my AWS Workshop documentation.
